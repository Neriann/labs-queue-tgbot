# Очередь для сдачи лаб в Telegram

Бот для выстраивания справедливой очереди сдачи лаб. Каждый ивент открывается командой `/new_event`. По дедлайну бот закрывает запись, разыгрывает порядок и публикует очередь в том же чате или теме. История и карма хранятся отдельно для каждого чата.

## Настройка Telegram

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и получите токен.
2. Скопируйте `.env.example` в `.env`. Заполните `BOT_TOKEN` и `BOT_TIMEZONE`. Для часового пояса используйте имя из базы IANA, например `Europe/Moscow` или `Europe/Helsinki`. Храните токен в локальном `.env`.
3. В личке отправьте боту `/start`. Для работы в группе добавьте бота и вызовите `/new_event@имя_бота`. Если BotFather запрещает добавлять бота в группы, включите эту возможность через `/setjoingroups`.
4. С включённым Group Privacy используйте команды с `@имя_бота` и отвечайте на вопросы бота через «Ответить». Если нужны команды без суффикса в любом контексте, в BotFather откройте `/setprivacy`, выберите бота и нажмите **Disable**. Затем удалите бота из группы и добавьте его снова.
5. Для автоматического закрепления задайте `PIN_EVENT_MESSAGES=true`. В группе выдайте боту права администратора с разрешением закреплять сообщения. При отказе Telegram карточка и запись продолжат работать.
6. Чтобы добавить команды в меню Telegram, отправьте `/setcommands` в BotFather и вставьте список ниже.

```text
new_event - Создать ивент
cancel - Отменить создание ивента
stats - Статистика чата
my_stats - Моя статистика
help - Справка
```

Подробнее о приватности и правах бота можно прочитать в [Telegram Bot Features](https://core.telegram.org/bots/features#privacy-mode) и [Telegram Bot API](https://core.telegram.org/bots/api#pinchatmessage).

## Запуск

### Docker Compose

В корне проекта выполните:

```bash
cp .env.example .env
# Заполните BOT_TOKEN и BOT_TIMEZONE в .env.
docker compose up --build
```

Для установки с отдельной командой Compose используйте `docker-compose up --build`. SQLite хранится в томе `queue-data` по пути `/app/data/queue.sqlite3`. Для проверки восстановления перезапустите контейнер через `docker compose restart bot`. Сохраняйте том при обновлении проекта.

### Локально

Требуются Python 3.11+ и SQLite 3.35+ в сборке Python. Запускайте команды из корня проекта:

```bash
cp .env.example .env
# Заполните BOT_TOKEN и BOT_TIMEZONE в .env.
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m bot
```

В PowerShell активируйте окружение командой `\.venv\Scripts\Activate.ps1`. При локальном запуске БД по умолчанию создаётся в `data/queue.sqlite3`.

Проект получает обновления через long polling. Запускайте один экземпляр на токен и БД. Используйте отдельного бота либо заранее снимите webhook старого приложения, если этот токен использовался там.

## Команды и дедлайны

| Команда | Что делает |
| --- | --- |
| `/new_event` | Запрашивает название и дедлайн, публикует карточку. |
| `/cancel` | Выходит из диалога создания. |
| `/stats` | Показывает приоритеты и число ивентов по участникам текущего чата. |
| `/my_stats` | Показывает долг и последние пять позиций в текущем чате. |
| `/help`, `/start` | Показывает команды и объясняет карму. |

| Ввод | Интерпретация |
| --- | --- |
| `+30m`, `+2h` | Через указанное число минут или часов. |
| `ДД.ММ ЧЧ:ММ` | Дата текущего года в `BOT_TIMEZONE`. Прошедшие даты отклоняются. |
| `ЧЧ:ММ` | Сегодня, если это местное время ещё впереди, иначе завтра. |

При вводе неоднозначного или несуществующего местного времени в день перевода часов бот попросит указать интервал. Дедлайны хранятся в UTC. Присоединиться и отменить запись можно до дедлайна или досрочного закрытия, смотря что наступит раньше. Кнопка досрочного закрытия видна на общей карточке. При нажатии бот проверяет, что пользователь создал ивент или администрирует группу.

Для одноимённых участников без username бот добавляет Telegram ID к отображаемому имени. В итоговой очереди имя ведёт на профиль. При бол1.00× соответствует новому участнику. Чем выше приоритет, тем больше шанс оказаться ближе к началу. Карма считается отдельно в каждом чате.
ьшом числе записей карточка показывает первые строки и число остальных, а итоговая очередь и статистика выходят несколькими сообщениями.

## Карма и приоритет

Стартовый долг равен `0.5`. Вес участника равен `(0.1 + debt) ** FAIRNESS_POWER`, где `FAIRNESS_POWER=1.8` по умолчанию. Значение на карточке выражено в весах нового участника, которому соответствует `1.00×`.

`fairness_power` влияет на силу смещения в пользу участников с большим долгом. Чем выше значение, тем сильнее накопленная задолженность влияет на шанс попасть ближе к началу очереди. Низкое значение делает выбор более близким к случайному, а высокое — более жёстко поддерживает справедливость по накопленным долгам.

Efraimidis–Spirakis сортирует участников по убыванию `u ** (1 / weight)` для независимых `u` из `[1e-9, 1.0]`. Код использует эквивалентную сортировку в логарифмической шкале для устойчивости при маленьких весах.

Для списка из двух или более человек бот обновляет долг по формуле `ALPHA * debt + (1 - ALPHA) * rank / (N - 1)`, где `rank` начинается с нуля и `ALPHA=0.5` по умолчанию. Единственный участник получает первое место с прежним долгом. `alpha` отвечает за скорость выравнивания: при большом `alpha` прошлый долг влияет сильнее, и очередь меняется медленнее; при меньшем `alpha` последнее положение получает больше веса, и долги выравниваются быстрее. Счётчик ивентов увеличивается у каждого участника итогового списка. Карма и счётчик обновляются при закрытии записи.

## Хранение и восстановление

- SQLite-транзакция сохраняет статус, позиции, долг и счётчики целиком. Проверка статуса и времени при записи тоже выполняется внутри транзакции.
- APScheduler 3.x держит таймеры в памяти. При старте бот читает открытые ивенты из SQLite, разыгрывает просроченные и восстанавливает остальные таймеры. Если процесс оборвался до привязки карточки к ивенту, при следующем старте такая запись получает статус `CANCELLED`.
- Правки одной карточки объединяются и отправляются с интервалом минимум в секунду. Для публикации карточки и итогов бот учитывает `retry_after`, а временные сетевые сбои обрабатывает повторными попытками.
- Очередь сохраняется до публикации. Бот запоминает уже отправленные страницы и при старте продолжает доставку. Если процесс оборвётся после принятия сообщения Telegram и до записи прогресса в SQLite, последняя страница может прийти повторно. Порядок и карма при этом сохраняются. Если Telegram отклоняет отправку из-за прав в чате, проверьте журнал, восстановите права и перезапустите бот.
- Незавершённые диалоги `/new_event` хранятся в памяти. После перезапуска начните такой диалог заново.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты используют настоящий SQLite, APScheduler и диспетчер aiogram. Проверка рестарта запускает два процесса Python с общей БД. Вызовы Telegram в тестах подменены, поэтому запуск тестов обходится без токена.
